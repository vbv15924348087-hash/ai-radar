# 每日精选与用户选题

用户于 2026-09-06 指定：先每日获取最新、权威的 AI 资讯，在 AI Radar 中浏览选题，再由 Codex 按选定内容总结成文与投稿。没有用户选题时，日常任务只更新阅读材料。

## 固定交付

- 时间：每天北京时间 20:00，沿用当前任务中的自动化 `ai`，名称为「每日权威 AI 资讯精选」。不要重复创建调度。
- 页面：http://127.0.0.1:3000/briefings ，主导航「每日精选」。
- 资料：`digests/YYYY-MM-DD.json`，附同名 Markdown；每天一份，可订正。同日已分配的资讯 ID 要稳定，不要重新编号指向另一件事。
- 用户选择：`selections/YYYY-MM-DD.json`，由用户在页面保存，包含 selectedIds、angle、updatedAt。生成简报时不要编辑、重置或代填此目录，也不要把 recommended 推荐标记当成用户选择。
- 发布状态：保存选题只是准备写作素材，页面不提交网站。后续用户指定成文、发文时，再按其指令继续。

## 检索与核验

先核对当前日期、北京时间截止时刻和历史简报，再检索最近 24 小时的一手资讯。必要时扩展至 72 小时或 7 天并明确标注，目标 6—10 条，宁缺毋滥。首期只是格式示例，后续须实时检索，不能循环使用首期内容。

优先官方发布、版本日志、模型卡、技术报告、开源仓库和原始研究；权威媒体用于背景和独立验证。实际打开原文，逐一确认发布/更新日期、功能开放范围、价格生效时间和关键事实。性能与收益属于厂商自报时要注明。研究区分预印本与同行评审结果。材料合并同一事件，避免一个模型及其 API 功能被重复计数。

只提供日期而无准确时间时，不能武断标为严格 24 小时内；可使用更宽的 72h 或 7d，并在 caveat 交代。使用更新日期判断近期性时，publishedAt 仍保存首发日，并在 caveat 说明更新时间。不确定日期的材料放入 coverageNotes，不进入带确定日期的主列表。

每条提供中文事实摘要、产品经理意义、可写角度、适用边界和少量逐字原文引文。公开出处支持事实，whyItMatters 和 angle 是分析。每期最多推荐 2—3 个选题方向；推荐不自动选中。若没有可靠更新，允许 items 为空，并如实写清覆盖范围；不要凑条数或声称全网无更新。

## 更新工作台

1. 阅读 `src/domain/digest.ts` 的类型和 `src/infrastructure/digests/store.ts` 的 Zod 约束，按结构生成当日 JSON。date / publishedAt 使用有效的 YYYY-MM-DD，generatedAt / windowStart 使用带时区的 ISO 时间；freshness 是 `24h`、`72h` 或 `7d`；每条 id 用 `YYYY-MM-DD-01` 等稳定编号，evidence 引用必须来自实际打开的原文，链接使用 HTTP(S)。
2. 把候选 JSON 写入临时准备文件，例如 `.qa/digest-inbox/YYYY-MM-DD.json`，先不覆盖正式目录。
3. 在项目目录运行 `npm run digest:import -- <候选 JSON 路径>`。脚本验证结构与链接后原子替换正式 JSON，并生成对应 Markdown；不会改变用户选题。无需调用付费 API，也不要依赖 AI Radar 的 development 规则分析生成中文总结。
4. 本地应用运行时检查 `GET http://127.0.0.1:3000/api/digests/YYYY-MM-DD`，确认最新内容与条数；新数据刷新即可，无需重新构建。若应用没有运行，可使用已有 `scripts/launch-radar.ps1 -NoBrowser -NoDialog` 启动，失败就交付 Markdown 并明确说明页面暂不可用。
5. 在当前任务发一次当日精选通知，附页面、日期、条数和 2—3 个选题方向。用户点击「保存选题」后，可复制写作请求或在任务中说“按已保存的选题整理”。读取该日期的 selection，不能将别的日期、已删除 ID 或自己的推荐当作用户选择。

本地定时运行需要电脑联网且 Codex 应用运行；Chrome 登录与作者认证不影响前置资讯任务。网站投稿要求作者实名认证，目前尚未验证通过，等用户要求投稿时再核对。
