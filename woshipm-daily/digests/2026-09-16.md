编号：2026-09-16-05｜原文日期：2026-09-15｜24 小时内｜AWS Machine Learning Blog

AWS 给出 Bedrock prompt caching 的六类实现：消息内容、系统提示词、工具定义、混合 TTL、租户隔离与 LangChain。Converse API 通过 cachePoint 缓存前缀；条目按 AWS 账户和 Region 隔离，默认 TTL 为 5 分钟，部分模型支持 1 小时，不同模型有最低 token 门槛。官方计价示例中缓存读取 token 比标准输入低 90%，缓存写入高 25%，1 小时缓存写入为标准输入的 2 倍。

**可写角度：**Prompt Cache 为什么需要命中率、TTL、租户边界和成功任务成本共同决策？

## 08 · 长时多 Agent 压测：识别威胁不等于阻断，污染可在 46 小时后继续触发

编号：2026-09-16-08｜原文日期：2026-09-15｜24 小时内｜arXiv 预印本

研究运行 8 个平行世界，每个世界 10 个 Agent，持续 16 天，共产生超过 85 万次 LLM 调用和近 500 亿 token。面对间接提示注入、错误信息和私有记忆暴露三类压力事件，没有一个世界全部通过；部分系统识别出威胁后仍继续交互、写入持久记忆，并在最长 46 小时后采取行动。

**产品经理视角：**Agent 安全验收需要覆盖长时状态、记忆污染、工具副作用、阻断和恢复。单轮回答安全或成功检测告警，不能证明系统已经控制风险。产品应记录威胁进入、传播、写入、调用工具和清理的完整链路，并验证中断后是否仍会再次触发。

**可写角度：**为什么长任务 Agent 的安全指标必须从检测率升级为阻断、清理与恢复？
