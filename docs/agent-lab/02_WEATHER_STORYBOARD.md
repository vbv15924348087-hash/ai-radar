以下均为本项目的**教学设计**：2026-09-05 为模拟“今天”，2026-09-04 为模拟“昨天”；城市固定成都；两天均比较最高气温、单位为摄氏度；初始值今天 30°C／晴、昨天 22°C／雨；本课数值输入范围 −80 至 60°C；每个逻辑查询最多尝试 2 次；本地纯规则模拟请求、返回检查、完成条件与建议。它们不是实时预报、真实模型调用或任何厂商接口保证。

## 2. 三档共用一条状态链

| 难度 | 目标 | 结束所需证据 | 操作重点 |
| --- | --- | --- | --- |
| A 一次查询 | 查询今天的最高气温 | 当前请求关联的有效今天事实 | 条件怎样变为请求；提出请求与程序执行的区别 |
| B 多步完成目标 | 查询两天、比较最高气温并整理建议 | 有效今天事实＋有效昨天事实＋比较结果 | 今天已知为何仍要查询昨天 |
| C 处理意外 | 在 B 的目标中处理错误返回 | 与 B 相同，或尝试耗尽后说明未完成原因 | 无效结果不进入事实；重试次数有上限 |

三档共享 `Run`、`Snapshot`、`WeatherRequest`、`ToolResult`、`WeatherFact` 和转换函数，差别为目标完成条件和界面开放的异常实验。系统不会先形成正确结论再追加“也可能失败”的装饰说明。

## 3. 逐事件脚本

“输入”和“前置”均指当前已发生的状态。工具数据只有显式提交并通过检查后才进入事实集合。操作栏中的“前进”包括用户下一步与播放器受控推进，但在人工等待点没有代替用户提交的权限。

| 步骤／事件 | 前置与输入 | 谁在做什么、画面变化 | 输出与下一步依据 | 可暂停解释与用户操作 |
| --- | --- | --- | --- | --- |
| W00 任务起点 | 已选择难度与模拟条件；没有天气事实 | 用户目标进入任务：城市、模拟日、最高气温口径可见 | 状态 `idle`，请求为空、尝试均为 0；开始后 W01 | 从哪里来：用户目标与本课模拟配置；可以改变难度、模拟温度或开始 |
| W01 可用工具 | 当前任务需要天气信息 | 展示开发者配置的 `get_weather` 工具名称、用途、必需条件 | 状态 `running`；不显示未来天气值；前进 W02 | 工具说明来自开发者配置；与某一次查询参数有何不同 |
| W02 组织参数 | 已知城市、基准日、查询口径 | 模型角色把用户条件放入请求表单；仍没有执行外部操作 | 下一次请求针对今天；前进 W03 | 参数小实验改变日期，看请求条件变化；实验副本不改主任务 |
| W03 提出请求 | 参数齐备 | 模型角色把请求交给应用程序；出现可追踪请求 ID | 请求 `proposed`，今天尝试仍为 0；前进 W04 | 提出调用请求（Function Calling）不等于执行成功；查看程序内容 |
| W04 程序发出今天请求 | 今天请求已提出，或 W13 请求重试 | 应用程序把请求交给模拟天气工具；请求方向为程序 → 工具 | 请求 `sent`；今天尝试＋1；仍无今天事实；前进 W05 | 实际执行者是谁；已发出与已获得结果为何不同 |
| W05 等今天结果 | 已发出的当前今天请求 | 用户扮演工具，选择本次返回、修改数值并提交 | 状态 `waiting`；下一步与自动播放均不能代替人工返回；提交后检查 | 执行后收到的结果（Observation）具体包含什么；只有“继续”为什么不够 |
| W06 今天结果检查 | 用户已明确提交当前请求的返回 | 应用程序校验请求 ID、城市、日期、单位、口径、数值与天气状态 | 有效结果进入 `facts.today`，状态 `running`；A 前进 W11，B/C 前进 W07；无效返回改走 W13 | 原始返回与有效事实不同；数据来源保留 `requestId`；可看检查原因 |
| W07 再看目标缺口 | 今天事实已有效，昨天仍未知 | 教学判断摘要指出“今天已知，还缺昨天”；今天来源持续可见 | 今天事实保留；下一步只查询昨天，前进 W08 | 一次返回为什么没有完成 B/C 的目标；当前可用信息不能出现昨天未来值 |
| W08 程序发出昨天请求 | 今天已知、昨天未知；或 W13 重试昨天 | 为昨天建立独立请求 ID 并由应用程序发给模拟工具 | 昨天请求 `sent`、昨天尝试＋1；前进 W09 | 本段压缩展示请求形成与发出；与今天请求使用同一工具、不同日期与 ID |
| W09a 等昨天结果 | 昨天请求已发出 | 用户只返回这一次昨天请求；今天事实保持 | `stage=W09,status=waiting`；下一步无效；必须明确提交 | 同一工具为何产生两个不同请求；不能把一份未被请求的两日答案同时喂入 |
| W09b 昨天结果检查 | 已明确提交当前昨天请求 | 程序采用与今天相同的规则检查；有效数据加入已知信息 | `stage=W09,status=running`，两日事实齐备但还没有比较结果；前进 W10；错误走 W13 | 格式上“成功”是否代表日期、口径正确；看原始返回及检查 |
| W10 计算 | 两日有效事实均存在 | 今天、昨天最高气温及其来源进入比较；本地计算今天减昨天 | `comparison` 生成，含差值、方向说明、建议和两个事实请求 ID；前进 W11 | 计算也是任务动作，但本例无需为算减法再调用外部工具 |
| W11 完成检查 | A 有今天事实；B/C 有两日事实与比较 | 应用程序检查本难度是否达到目标；页面展示证据清单 | 达标前进 W12；若数据不足则 W13 `incomplete`，不能形成确定结论 | 为什么可以结束；播放到了末尾不代表目标已满足 |
| W12 成功结束 | 对应难度的完成条件已满足 | 最终回答出现：A 返回今日查询；B/C 返回两日、差值与依据今天天气的建议 | `success`；不再自动推进；回答可回溯到请求与事实 | 完成（Finish）依据是什么；可回放、改条件或从头开始 |
| W13a 返回无效，可重试 | 当前请求已提交，校验失败，且本查询仅尝试 1 次 | 显示具体错误；原始异常返回留在历史，有效事实不变 | 状态 `running`；前进只重试当前逻辑查询，今天到 W04、昨天到 W08；使用新 ID | 路径为什么改变；已有今天数据为什么继续保留 |
| W13b 未完成停止 | 同一逻辑查询第 2 次返回仍无效 | 显示停止原因、失败证据与重新开始入口 | `incomplete`；无最终回答、无确定温差，不再发出第 3 次请求 | 成功结束与停止尝试不同；不能因没有结果而补造天气 |
| 任意非结束步骤：用户停止 | 任务仍可推进或等待 | 取消旧调度修订，保留可检查历史，明确显示用户停止 | `cancelled`，与工具失败、播放器暂停分开；旧返回不再写入 | 可以查看历史或从头开始；停止不是答错、也不是学习完成 |

W09 使用两个离散快照而非两个步骤 ID，页面以 `status` 区分“等待用户返回”与“已经检查”。W13 是在原规格 W00–W12 之外显式补入的异常分镜。动画只显示这些离散快照之间的变化，不负责决定业务事实何时成立。

## 4. 请求与返回协议

引擎内部使用 `requestId`，与开发规格示例的 `callId` 是相同职责的关联字段，属于本课协议命名选择。

```json
{
  "id": "本次运行ID:r0:today:attempt1",
  "logicalQuery": "today",
  "tool": "get_weather",
  "city": "成都",
  "date": "2026-09-05",
  "metric": "daily_high",
  "unit": "celsius",
  "status": "sent"
}
```

```json
{
  "requestId": "本次运行ID:r0:today:attempt1",
  "status": "success",
  "data": {
    "city": "成都",
    "date": "2026-09-05",
    "metric": "daily_high",
    "unit": "celsius",
    "value": 30,
    "condition": "晴"
  },
  "provenance": "teaching_fixture"
}
```

请求 ID 包含本次运行 ID、运行修订、逻辑查询和本查询的尝试次数。重试、查询另一天或建立新修订时不会共用请求 ID。有效事实拥有自己的数据 ID，并记录生成它的请求 ID。比较结果记录两份事实对应的请求 ID，最终结论由当前有效状态生成。

提交前的温度表单校验不算新工具执行；空字符串、空格、非法数值、非有限数值及超范围值不能变为温度 0。请求在“发出”时才增加尝试次数。返回缺字段、日期错、单位错、口径错、城市错、关联 ID 错都不能进入事实。已处理旧请求的迟到结果会被忽略，不能冒充当前请求的失败或成功。

## 5. 可操作分支与预期证据

| 分支 | 操作 | 预期证据 |
| --- | --- | --- |
| 正常 | 今天 30、昨天 22 | 两次独立请求，结果 +8°C；说明今天最高气温更高 |
| 负温差 | 今天 18、昨天 22 | −4°C；“比昨天低”；建议依据今天 18°C 与天气 |
| 零温差 | 今天 22、昨天 22 | 0°C；明确两日最高气温相同 |
| 超时后恢复 | 昨天首次超时，再提交有效返回 | 今天事实与来源保留；昨天新 ID、尝试 2；可成功 |
| 日期错误 | 昨天请求返回今天日期 | 明示所需日期 2026-09-04；不产生昨天事实和温差 |
| 缺字段 | `success` 返回删掉 value | 明示缺温度，绝不将缺值视为 0 |
| 单位／口径错误 | 返回 fahrenheit／daily_low | 指出不匹配项，并进入同一有界重试机制 |
| 两次失败 | 同一查询连续返回无效结果 | 状态为未完成停止；无第 3 次请求、无成功标识、无确定温差 |
| 改昨天条件 | 完成后修改昨天模拟值 | 保留已发生的今天事实及前缀；旧昨天、比较和回答失效；新修订从待查昨天处继续 |
| 改今天条件 | 已有事实后修改今天模拟值 | 回退至请求形成前的安全前缀；今天及其后的依赖事实失效；旧修订回调无效 |
| 历史重新提交 | 回到曾等待昨天的位置并明确提交新值 | 建立新修订、截掉旧未来；重新计算依据新提交，而非保留旧结论 |
| 用户停止 | 在等待或动作中停止 | 任务取消，播放器不再调度；保留历史检查入口与重新开始入口 |

如果改条件发生在尚未返回的今天请求上，即使只改了昨天配置，也会退到本次请求形成前的安全前缀，以取消未完成旧请求的调度。已经通过检查的今天事实在只改昨天时保留；未来未观看位置不作为可保留前缀。

## 6. 状态、回放与恢复约定

任务状态由 `Run`／`Snapshot` 管理：`idle`、`running`、`waiting`、`success`、`incomplete`、`cancelled`。播放、暂停、速度、动画子进度、解释展开属于播放器；理解检查属于本机学习状态，不能混入任务成功判断。

核心 API：`createRun` 新建，`advance` 推进，`submitResult` 明确提交，`makeResult` 仅构造候选，`seek` 定位已访问快照，`reviseRun` 修改输入，`cancelRun` 用户停止，`serializeRun`／`restoreRun` 保存与验证。所有转换不修改输入运行，不依赖系统时间、CSS 或动画完成事件。

回放通过已有快照移动游标，前进已有历史不重新发出请求、不增加尝试、不重新提交结果。主课术语解释暂停播放器并保留位置与子进度；关闭仍然暂停。术语实验默认只操作副本，明确应用到主任务时才建立上游修订。

播放器的旧回调应同时验证 `run.id` 与 `revision`，并在暂停、切换模式、改条件、重开和卸载时取消调度。引擎也验证预期修订。每次从头开始由界面产生新的运行 ID，以免另一场运行同为 `revision=0` 时发生混淆。

引擎保存格式有命名空间 `agent-lab.weather.run` 与版本 1。恢复不仅检查 JSON 结构，还逐条重新演算保存的事件，拒绝篡改事实、未来数据、伪造成功、无效修订和不兼容版本。播放器保存子进度，并在刷新恢复后强制暂停；引擎恢复不会执行任何新请求或提交。

## 7. 理解检查与验收脚本

1. **找来源**：今天结果已通过检查、昨天还未查询时，选出当前可用的信息。预期能指出目标和今天已返回数据可用，昨天仍未知；界面不能提前用配置默认值作为事实。
2. **选下一步**：B/C 今天 30°C 已知后选择下一步。预期选择查询昨天，因为比较所需的第二份事实还缺失；不是重复查询今天或提前生成温差。
3. **指出执行者**：停在 W03，判断天气是否已成功查询。预期指出请求刚提出，应用程序仍需发出请求，模拟工具返回后才能获得结果。
4. **改结果解释差异**：昨天返回从 22 改为 35，今天保持 30。预期先丢弃旧昨天与比较，再得到 −5°C；能指出变化来自本次昨天返回。
5. **检查停止**：同一查询连续失败两次，辨别“任务成功”“未完成停止”“播放器暂停”。预期选择未完成停止，解释缺有效数据且已到本课重试上限。

实际运行验收要分别检查：请求动画中途暂停与恢复；打开参数实验再退出位置不变；完整 B 流程及回放不增次数；负／零温差；错误日期；先失败再成功；连续失败停止；人工模式只按下一步仍等待；快速切换、重开与旧回调取消；刷新恢复默认暂停；损坏存储有重置；键盘操作、弱动画、窄屏布局。单元测试通过不能替代浏览器检查，具体执行证据写入 QA 报告。
